# design

用于新项目初始化或更新已有项目设计规范的 skill，生成标准化的 DESIGN.md 文件。

## 适用场景

- 新项目启动，需要建立完整的设计规范体系
- 已有项目需要更新或扩展设计 token、组件规则
- 用户提供了 Figma 链接、参考图或设计稿，需要落地为可用的设计规范文档
- 页面交付流程的第一步，确立项目级设计规则

不适用于：临时修改、小 bug 修复、零碎问题等非交付类任务；单页面结构拆解应直接进入 spec。

## 前置条件

无上游 skill 依赖，是页面交付流程的起点。

需要用户提供：
- 产品类型、端类型（Web / 移动 / PC 等）
- 品牌信息（品牌色、气质、关键词）
- 目标用户描述
- 参考图、原型图或 Figma 链接（如有）
- 已有组件库或 UI 框架信息（如有）

## 输出产物

- `DESIGN.md`：包含 YAML 前置数据（design token）和 Markdown 正文（设计理由说明）
  - 覆盖：品牌气质、色彩系统、字体系统、布局间距、阴影层级、圆角、组件规则、设计规范

## 下游 skill

- **spec**（优先）：基于 DESIGN.md 进行单页面结构拆解
- **handoff**：生成交付文档
- **implement**：依据设计规范实现页面代码
