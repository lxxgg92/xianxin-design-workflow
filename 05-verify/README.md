# verify

通过截图对比验收页面实现质量，生成包含偏差等级和修正建议的偏差报告。

## 适用场景
- implement 完成后，需要验证页面视觉还原度
- 用户提供了参考图（Figma 截图、原型图等），需要与实现截图做对比
- 需要系统性检查布局、字体、颜色、组件、状态、交互、响应式 7 个维度
- 迭代修改后，需要确认偏差是否已修复

## 前置条件
- 依赖 **implement** 的输出：页面代码已完成，页面能正常访问
- 需要用户提供参考图（Figma 截图、原型图或设计稿截图）
- 项目中存在 DESIGN.md、UI_SPEC.md（或对应页面的 UI_SPEC_*.md）

## 输出产物
- 偏差报告，包含：
  - 符合的地方
  - 不符合的地方
  - 偏差等级（严重 / 中等 / 轻微）
  - 修正建议
  - 是否需要继续修改代码

## 下游 Skill
- 轻微偏差 / 无偏差 → **deliver**
- 严重偏差 → 回退到 **implement**

## 如何使用

| 工具 | 触发方式 |
|------|----------|
| Kiro | `/verify` |
| OpenAI Codex CLI | 全局安装后对话描述需求，或在项目根目录说明意图 |
| Claude Code | `/verify` |
| Cursor | 在对话中说"`verify`"或描述需求（如"帮我初始化项目设计规范"） |
| Windsurf | 在对话中说"`verify`"或描述需求 |
| Trae | 在对话中说"`verify`"或描述需求 |
| 通用 AI 助手 | 粘贴 `skill.md` 内容后描述需求 |

**自动化选项（Workflow）**：如果需要并行检查 7 个验收维度，可以运行：
```
使用 workflow 运行 screenshot-verify
```
自动化版本会用 7 个 agent 并行检查，最后汇总成一份偏差报告，比手动逐项检查更快。
