# spec

拆解具体页面的结构与模块，生成标准化的 UI_SPEC.md 文件。

## 适用场景
- 设计稿或页面需求已明确，需要将其拆解为可供开发实现的结构化 UI 规范
- 项目级设计规范（DESIGN.md）已就绪，进入单页面拆解阶段
- 用户直接提供页面需求，需要生成实现前的 UI Spec

## 前置条件
- 依赖 **design** 的输出：项目根目录必须已存在 DESIGN.md
- 如果 DESIGN.md 尚未生成，需先运行 design

## 输出产物
- `UI_SPEC.md`（单页面项目）
- `UI_SPEC_页面名.md`（多页面项目，如 `UI_SPEC_用户列表.md`、`UI_SPEC_订单详情.md`）
- 固定包含 8 个章节：页面目标、页面结构、模块拆解、字段说明、交互规则、状态规则、响应式规则、视觉规则引用

## 下游 Skill
- **handoff**：UI Spec 经用户确认后，交由 handoff 拆解为开发任务

## 如何使用

| 工具 | 触发方式 |
|------|----------|
| Kiro | `/spec` |
| OpenAI Codex CLI | 全局安装后对话描述需求，或在项目根目录说明意图 |
| Claude Code | `/spec` |
| Cursor | 在对话中说"`spec`"或描述需求（如"帮我初始化项目设计规范"） |
| Windsurf | 在对话中说"`spec`"或描述需求 |
| Trae | 在对话中说"`spec`"或描述需求 |
| 通用 AI 助手 | 粘贴 `skill.md` 内容后描述需求 |

### 触发所需信息
- 页面需求说明（页面要做什么）
- 截图 / Figma 链接 / 参考图（至少一项）
- 目标端（PC / 移动端 / 响应式）
- 字段说明（如有）
- 交互说明（如有）
