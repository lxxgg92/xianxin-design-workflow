# spec

拆解具体页面的结构与模块，生成 UI_SPEC.md。在 design 完成后由用户确认进入，或用户直接提供页面需求时触发。负责单页面拆解；项目级设计规范由 design 负责。不应在 DESIGN.md 未完成时触发。

## 前置判断
- 执行前检查项目根目录是否已有 DESIGN.md；如果没有，拒绝执行并提示用户先运行 design
- 如果当前任务是建立或补全项目级设计规范，而不是拆解某个具体页面，应回到 design，不直接生成 UI_SPEC.md
- 执行前检查是否已有 UI_SPEC.md 或 UI_SPEC_*.md：
  - 如果已有：告知用户当前已存在的文件名，询问是追加新页面还是覆盖现有内容，等用户确认后再继续
  - 如果没有：直接进入信息收集
- 检查用户是否提供了足够信息，缺少信息时，**不要逐条追问**，一次性整理所有缺失项后统一反馈：
  - 页面需求说明（页面要做什么）
  - 截图 / Figma 链接 / 参考图（至少一项）
  - 目标端（PC / 移动端 / 响应式）
  - 字段说明（如有）
  - 交互说明（如有）

## 输入
- 页面需求文档
- 截图 / Figma 原型 / 参考图
- 字段说明
- 交互说明
- DESIGN.md（视觉规则引用来源）

## 输出
- UI_SPEC.md 文件（Markdown 格式，按章节组织）
- 单页面项目直接命名为 UI_SPEC.md；多页面项目按页面名区分，如 UI_SPEC_用户列表.md、UI_SPEC_订单详情.md
- 章节结构：
  - ## 页面目标
  - ## 页面结构
  - ## 模块拆解
  - ## 字段说明
  - ## 交互规则
  - ## 状态规则
  - ## 响应式规则
  - ## 视觉规则引用

## 暂停点
- UI Spec 输出完成后，必须暂停，告诉用户：
  "这是页面实现前的 UI_SPEC.md，如果你确认，我再继续运行 handoff。"
- 不要在用户确认前自动进入下一步

## 职责
拆解页面结构与模块，输出以下 8 个章节：

1. **页面目标**：目标用户、页面解决的问题、用户最主要的操作目标
2. **页面结构**：顶部区域、筛选区域、数据概览区域、主内容区域、侧边栏、底部操作区、弹窗/抽屉/二级页面
3. **模块拆解**：模块名称、作用、展示字段、操作按钮、默认/空/加载/错误/权限状态
4. **字段说明**：字段名称、含义、类型、是否必填、示例数据、展示规则、异常规则
5. **交互规则**：点击动作、筛选生效方式、搜索触发、分页规则、表单校验、弹窗逻辑、删除确认、成功/失败反馈
6. **状态规则**：
   必须说明每个状态的**具体实现方式**（不只是列出状态名称）：
   - **默认态**：正常数据展示
   - **空状态**：
     - 触发条件（数据为空、筛选无结果、首次进入）
     - 使用组件（引用 DESIGN.md 中定义的 Empty 组件或占位符）
     - 文案模板和操作引导（如"暂无数据，点击新建"）
   - **加载态**：
     - 首次加载：骨架屏（引用 DESIGN.md 定义）或 loading spinner
     - 刷新加载：loading 位置和样式
     - 加载超时处理（如超过 10s 提示超时，提供重试按钮）
   - **错误态**：
     - 错误分类（网络错误、权限错误、服务错误、数据格式错误）
     - 每类错误的提示文案
     - 重试/刷新操作
   - **数据异常态**：
     - 字段缺失时的默认值或占位符（如 "--"）
     - 数据格式错误时的降级展示
     - 部分数据加载失败时的处理（显示已加载部分，标注失败部分）
   - **性能约束**（针对大数据量场景）：
     - 列表超过 100 条：必须使用虚拟滚动（如 react-window）或分页加载
     - 图片：必须懒加载，提供占位图，加载失败有降级方案
     - 大数据集渲染：增量加载或使用骨架屏提升感知性能
   - **hover 态、active 态、disabled 态**：交互反馈样式
7. **响应式规则**：桌面端、平板端、移动端堆叠方式、表格小屏处理、按钮收起逻辑
8. **视觉规则引用**：使用 DESIGN.md YAML 中定义的 token 名标注（如 `{colors.primary}`、`{typography.body-md}`、`{spacing.base}`），不直接写具体数值，包括配对色（如使用 {colors.primary} 作为背景色时，必须配合 {colors.on-primary} 作为文字色，确保 WCAG 对比度达标）

- 依赖：DESIGN.md
- 输出：UI_SPEC.md，供 handoff 使用
- 下游：→ handoff
